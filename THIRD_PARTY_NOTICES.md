# BSL.v68

`Classes/Packets/Server/Home/OwnHomeDataMessage.py` and `Classes/Crypto.py`
are Python adaptations of [LkPrtctrd/BSL.v68](https://github.com/LkPrtctrd/BSL.v68),
revision `a7374496b27489605c596b640e2831f5def61249`:

- `BSL.v68.Logic/Protocol/Laser/S/OwnHomeDataMessage.cs`
- `BSL.v68.Logic/Messaging.cs`
- `BSL.v68.TitanEngine/NaCl/TweetNaCl.cs`
- `BSL.v68.TitanEngine/Pepp/` and `BSL.v68.TitanEngine/Blake/`

The upstream repository distributes this code under the Apache License 2.0.
The license is reproduced in `licenses/BSL.v68-Apache-2.0.txt`.

Changes: translated to Python, connected home/avatar IDs and the avatar name to
the local player, used cryptography's X25519 and Poly1305 primitives, and integrated
the Pepper session with the threaded and asyncio transports. The home encoder
also includes v70 field-order changes identified in the local iOS databases;
see `docs/own-home-v70.md`.

`tests/fixtures/bsl_v68_vectors.json` contains outputs generated by running the
upstream C# encoder and TweetNaCl implementation with deterministic inputs.
`tests/fixtures/own_home_v70.hex` records the corrected Python encoder after
validation against the live native v70 decoder, using player ID `[0, 1]` and
name `LkPrtctrd`. It is a regression fixture, not a captured live-client packet.

`scripts/v70-ios.js` includes a JavaScript adaptation of the XSalsa19-Poly1305
implementation and compatibility constants from `Classes/Crypto.py`, together
with native v70 hooks and socket redirection. It uses the same upstream license.
